## 一句话定位

知微高数是一套面向大学高等数学学习的确定性 AI 辅导工具：学生可以直接输入、
拍照或语音提问，系统先识别并让学生确认题目，再用 SymPy 统一求解器计算，最后以
结构化步骤、知识点和错题复习的方式返回结果。

## 项目背景

高数学习中的典型问题不是“没有答案”，而是：

- 通用大模型可能给出流畅但错误的公式推导，学生难以判断。
- 拍照识题、公式排版、二次确认和计算过程常分散在不同工具里。
- 学生知道答案错误时，仍缺少“错在哪一步、对应哪个知识点”的反馈。
- 手机端软键盘、长公式、多题图片和慢网络会打断学习流程。

本作品把“识别、确认、计算、讲解、复习”组织成一条完整链路，并将最终数学计算与
语言模型解耦。

## 目标用户与场景

- 大学本科低年级学生：课后练习、错题复盘、章节知识检索。
- 教师或助教：快速验证常见高数题和候选答案。
- 演示与评审场景：无需登录即可直接体验公网页面。

## 核心能力

### 确定性数学求解

- 支持 9 个章节类别、45 个求解主题。
- 覆盖极限、导数、积分、微分方程、向量、多元函数微分、重积分、曲线曲面积分和
  无穷级数。
- 支持求导、积分、极限、统一章节求解、候选答案判定和函数图像 SVG。
- 数学结果由 SymPy 计算，不让通用语言模型直接决定最终答案。

### 图片识题与二次确认

- 支持相机、相册、拖放和剪贴板上传图片。
- 单次最多选择 4 张题目图片，单张图片限制 6 MB。
- 视觉 OCR 为公网主链路，扣子 OCR 为备用，Windows OCR 仅作本地最后降级。
- 识别后先展示原文，学生确认后才进入计算。
- 多题图片先让学生选择题目，失败或残缺时要求重传，不猜测公式。
- 相同图片使用 SHA256 缓存，减少重复识别和等待。

### 学习空间

- 无需登录的独立演示页，兼容桌面端和移动端。
- 数学公式使用本地 KaTeX 渲染，不依赖外部公式 CDN。
- 对话历史只保存在当前浏览器 `localStorage`。
- 提供知识点提示、错题集、重练、导出、清空和学习进度。
- 支持浏览器原生中文语音输入和回答朗读。

### 稳定性与安全

- 默认每分钟 60 次请求限流，可在部署环境调整。
- 表达式和符号长度受限，计算结果有超时保护。
- 图片类型、响应体大小和上游超时均有边界检查。
- 服务日志默认不保存原始数学表达式。
- `MATH_API_KEY` 可启用，以备正式环境保护计算接口。
- 移动端适配软键盘和安全区，OCR 客户端超时为 90 秒。
- 慢请求在 8 秒和 22 秒显示不同进度提示，避免重复提交。

## 技术架构

```text
浏览器学习空间
├─ 文本输入 / 图片上传 / Web Speech API
├─ 本地对话、错题集和学习进度
└─ /demo/api/*
        │
        ▼
Flask WSGI 部署入口
├─ 对话意图与题目清理
├─ OCR 二次确认和会话状态
├─ 知识检索
└─ 通用问答模型，仅处理非数学问题
        │
        ├─ 数学问题 ──> SymPy 统一求解器 ──> 结构化结果与 LaTeX
        └─ 图片问题 ──> 阿里云百炼视觉 OCR
                         └─ 失败时切到扣子 OCR
```

关键技术选择：

- 语言模型负责理解表达和组织自然语言，确定性数学工具负责结果。
- OCR 不做“猜题式修复”，而是用二次确认把识别风险交还给学生。
- PythonAnywhere 使用同步 Flask WSGI 入口，避免本地异步部署入口的兼容问题。
- GitHub Actions 在干净环境运行完整测试、公网部署验收和固定回归。

## 答辩问答

### 为什么不能直接让大模型算题？

大模型擅长理解自然语言，但生成式输出不能天然保证数学正确。本项目让模型负责理解
和表达，最终求导、积分、极限和章节题由 SymPy 等确定性逻辑完成，还可以对候选答案
做结构化比较。

### 图片识别错了怎么办？

系统不自动猜公式。识别后必须由学生确认；识别残缺、为多题或结果不可信时，页面会
要求选择题目或重新上传。这样可以避免把 OCR 错误静默带入计算。

### 为什么保留扣子 OCR？

视觉模型是主链路，扣子 OCR 是独立上游。保留备用链路可以在单一下游故障时提高可用性。
如果正式评估后认为运维成本高于收益，可以按部署文档下线备用链路。

### 如何保护学生数据？

演示页对话默认只保存在浏览器本地，不写入跨用户共享的对话数据库。服务端会话为进程
内存，30 分钟过期；OCR 缓存 10 分钟过期，并带容量上限。正式发布前可启用 API Key、
持久日志策略和隐私说明。

### 当前技术边界是什么？

- 服务端会话和 OCR 缓存保存在进程内存，Web 应用 Reload 后会清空。
- 语音识别依赖浏览器厂商服务，并非完全离线。
- OCR 复杂旋转、遮挡和低质量图片仍有拒绝率。
- 演示阶段日志关闭，正式上线前需要重新评估持久日志、告警和任务队列。
- 云模型额度、限流和余额需要从云平台控制台确认。

### 项目的创新点是什么？

- 将生成式语言理解和确定性数学计算拆开，明确每部分的责任边界。
- 将 OCR 二次确认、数学求解、知识点、错题复习和移动端适配串成完整学习链路。
- 用固定样例、固定种子随机题和公网回归共同约束计算结果，而不是只演示成功案例。
